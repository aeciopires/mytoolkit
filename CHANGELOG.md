# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.2.0] - 2026-11-16

### Added

- JWT: offline key generation, JWKS, and custom claims (all via `golang-jwt/jwt/v5`, nothing ever fetched from the network).
  - **Key generation**: `mytoolkit jwt keygen` / REST `mode: keygen` / MCP `jwt_keygen` — HMAC secret (+ `oct` JWK), or RSA (2048/3072/4096), EC (P-256/384/521 matching ES256/384/512) and Ed25519 key pairs as PKCS#8/PKIX PEM + private/public JWK + a ready-to-publish JWKS. Default `kid` is the RFC 7638 thumbprint. `--private-out` writes the private key with mode `0600`.
  - **JWKS**: `mytoolkit jwt jwks` / REST `mode: jwks` / MCP `jwt_jwks` — converts PEM keys/certificates (multiple blocks → multi-key set), a JWK or a JWKS into a public-only JWKS.
  - **Signing with claims**: `--iss`, `--sub`, `--aud` (repeatable), `--exp`/`--nbf` (durations, incl. `7d`), `--iat`, `--jti`, `--kid`, and `--claim name=value` custom claims — repeated names or `name[]=value` produce a list of strings. Same options on REST (`issuer`, `subject`, `audience`, `expires_in`, `not_before`, `issued_at`, `jwt_id`, `kid`, `claims`) and MCP `jwt_encode` (`custom_claims`). Private keys may also be given as a private JWK.
  - **Verification**: `key` now also accepts a JWK, a JWKS (key picked by the token's `kid`), a private key or a certificate; `exp`/`nbf`/`iat` are validated; a new `verify_error` field explains `valid: false`.
  - Web page: four modes (Decode/Verify, Encode, Generate Key, Build JWKS) with registered-claim fields and a one-claim-per-line custom claims box; verified with Playwright through the full keygen → sign → JWKS → verify flow.
- MCP: `jwt_keygen` and `jwt_jwks` (18 MCP tools in total).
- `make helm-check-version` (a prerequisite of every `helm-*` target) and a Helm-major-version check in `make check-tools`.
- Graceful shutdown on SIGINT/SIGTERM for `serve` and `mcp --transport http` (20s drain, below Kubernetes' default 30s grace period).
- **Observability stack — metrics, logs and traces** (`docker-compose.yml`, `observability/`): Grafana 13.3.1, Prometheus 3.16.0, Loki 3.7.10, Tempo 3.1.1, Jaeger 2.23.0 and Grafana Alloy 1.22.0, fully provisioned and cross-linked (Prometheus exemplars → Tempo, Loki `trace_id` → Tempo, Tempo/Jaeger spans → Loki logs, Tempo → Prometheus span metrics and service map). Alloy ships every Compose container's JSON logs to Loki (level normalized, `level`/`tool` labels, `trace_id`/`span_id` as structured metadata) and fans OTLP traces out to Tempo and Jaeger; Tempo's metrics generator remote-writes RED metrics and the service graph to Prometheus. Every component logs JSON too. Prometheus also scrapes the stack itself.
- **OpenTelemetry tracing** (`internal/telemetry`), opt-in via the standard `OTEL_*` variables (OTLP/HTTP): REST server spans named after the chi route plus a `tool <slug>` child span; one MCP span per JSON-RPC request (`mcp tools/call <tool>`), honoring `traceparent` from HTTP headers or MCP `params._meta`. Latency histograms record `trace_id` **exemplars** (`/metrics` now negotiates OpenMetrics).
- Grafana dashboards **"MyToolkit — Logs"** (log volume by level/service, errors/warnings, requests, p95 latency and HTTP status derived from the JSON request logs, live log panels filterable by service/level/tool/regex) and **"MyToolkit — Traces"** (RED metrics per operation from span metrics with exemplars, service map, recent/error/slow traces and tool spans via TraceQL, trace view by ID in Tempo and in Jaeger). The metrics dashboard gained exemplars on every latency panel, links to the other dashboards/Explore apps/Jaeger UI, and an "Observability Stack" targets-up row. All three verified by running every panel query through Grafana's API against real traffic and by Playwright screenshots.
- **JSON logging everywhere** (`internal/logging`): every `serve`/`mcp` stderr line is one JSON object with `level`, `service`, `version`, `time` (RFC 3339 nanoseconds) and `message`; request lines add `trace_id`/`span_id`; stdlib `log` (incl. `http.Server.ErrorLog`), `log/slog` and OTel SDK errors are routed into it; a fatal server error (e.g. port in use) is a JSON `error` line instead of plain text. MCP logs one line per JSON-RPC request.
- **Health checks for the MCP server**: `mytoolkit mcp --transport http` now serves `GET /healthz` and `GET /readyz` (shared `internal/health` package with the web server). `/readyz` returns `503 {"status":"shutting_down"}` once graceful shutdown starts, and the new `MYTOOLKIT_SHUTDOWN_DELAY` keeps serving that long with readiness failing before closing the listener. `mytoolkit healthcheck` gained `--mcp` and `--path`.
- Helm chart **1.1.0**: MCP probes switched from `tcpSocket` to `httpGet` `/healthz`/`/readyz`; `helm test` checks both endpoints on the web and (when enabled) MCP Services; new `tracing.*` values (`enabled`, `endpoint`, `sampler`, `samplerArg`, `resourceAttributes`) rendered as `OTEL_*` variables; `env.shutdownDelay` (default `5s`) and `terminationGracePeriodSeconds`; `checksum/config` pod annotation so ConfigMap changes roll the pods. Verified on a throwaway kind cluster (`helm install` with MCP + tracing, `helm test`, probes, graceful shutdown).
- `make compose-up` passes the repo `VERSION` into the image build (Compose `VERSION` build arg) and starts the whole stack; `make compose-down` also stops the `mcp` profile.

- Go code modernized following JetBrains' [`use-modern-go`](https://github.com/JetBrains/go-modern-guidelines) guidelines and `go fix`: `errors.AsType`, `slices.Contains`/`SortFunc`, `cmp.Or`, `atomic.Int64`, `t.Context()`, `new(value)`, `range` over ints, and `encoding/json/v2` for new JSON parsing (existing wire output intentionally unchanged).
- JWT REST: an unknown `options.mode` now returns `INVALID_OPTION` instead of silently decoding.
- JWT registry description updated to reflect the new capabilities.

### Fixed

- **Security — JWT `HS*` signing accepted an empty secret**, producing tokens anyone could forge. Now `400 MISSING_SECRET`.
- **Security — JWT verification of an `HS*` token with only `key` supplied used an empty HMAC key**, so a token forged with an empty secret reported `valid: true`. It now reports `valid: false`.
- **Security — duplicate claim names** (`{"sub":"alice","sub":"admin"}`) were silently accepted (last wins); now rejected as `INVALID_CLAIMS`.
- JWT: EC key on the wrong curve for `ES*` returned `500 SIGNING_FAILED`; now `400 INVALID_KEY` with the expected curve. Invalid claims JSON returned code `INVALID_TOKEN`; now `INVALID_CLAIMS`. A token string with surrounding whitespace/newline is now trimmed before decoding.
- **Data race** in `metrics.Ranking()`: it iterated the usage map without the mutex while `RecordUsage` inserted into it — a fatal `concurrent map iteration and map write` under load. Regression test runs under `-race`.
- HTTP servers had no timeouts (Slowloris-prone) and REST tool requests had no body size limit (memory exhaustion); now `ReadHeaderTimeout`/`ReadTimeout`/`IdleTimeout` are set and bodies are capped at 10 MiB.
- CLI errors printed the full usage text and the error message twice; now a single `Error: …` line on stderr.
- `mytoolkit jwt --encode` with only claim flags no longer blocks waiting for stdin when stdin is an interactive terminal.
- **MCP server crash**: a handler panic (e.g. reading `_meta` from the typed-nil params of `notifications/initialized`) unwound through the SDK's unrecovered goroutine and killed the whole `mytoolkit mcp` process; panics are now recovered into JSON-RPC errors (and the nil-params case no longer panics).

## [1.1.0] - 2026-07-20

### Added

- MCP (Model Context Protocol) server: a 4th surface alongside the web UI, REST API, and CLI, exposing all 15 tools as 16 MCP tools (JWT splits into `jwt_encode`/`jwt_decode`) via the new `mytoolkit mcp` subcommand. Built on the official `github.com/modelcontextprotocol/go-sdk`, it calls the exact same `internal/tools/<name>` pure functions the other three surfaces already call — zero duplicated business logic. Lives at `app/internal/mcp/` (one file per tool, self-registering via `init()`, mirroring `internal/cli/<name>.go`'s pattern) plus `app/internal/cli/mcp.go` for the cobra wiring; `mcp/README.md` at the repo root documents installation and client configuration (Claude Desktop, Claude Code), with example config files under `mcp/examples/` and a Mermaid workflow diagram.
- Two transports: `stdio` (default, for local MCP clients) and streamable `http` (`--transport http --port 8081`, for a shared/remote MCP endpoint), configurable via `MYTOOLKIT_MCP_TRANSPORT`/`MYTOOLKIT_MCP_PORT`/`--transport`/`--port` following the same flag > env > default precedence as every other MyToolkit setting.
- `qrcode`'s MCP tool returns an `image/png` content block (base64 on the wire) rather than JSON text, and `k8s-validate`'s MCP tool matches the REST endpoint's behavior of treating a parseable-but-semantically-invalid document as a successful call (`isError: false`) whose structured result reports `"valid": false` — both documented exceptions, not oversights.
- `helm/mytoolkit`: optional `mcp.enabled` Deployment/Service pair (same image, `args: ["mcp", "--transport", "http", ...]`, TCP-socket liveness/readiness probes since the MCP endpoint isn't a plain HTTP GET target), plus its own dedicated ConfigMap, and optional HorizontalPodAutoscaler (`mcp.autoscaling.enabled`), PodDisruptionBudget (`mcp.pdb.enabled`), ServiceAccount (`mcp.serviceAccount.create`, falls back to the shared ServiceAccount when disabled), Secret (`mcp.secret.enabled`), and Ingress (`mcp.ingress.enabled`) — mirroring the equivalent toggles already available for the main Deployment. `docker-compose.yml`: optional `mytoolkit-mcp` service under the `mcp` Compose profile. `Makefile`: `mcp-run`/`mcp-run-http` targets.
- Verified end-to-end against the real built binary: a throwaway MCP client driving `mytoolkit mcp` over both a real `os/exec` stdio subprocess and a `curl` streamable-HTTP handshake — `tools/list` (16 tools), a `base64` round trip, an intentionally invalid option producing `isError: true`, `k8s-validate`'s non-error semantic-invalid result, and `qrcode`'s image content block all confirmed against actual output, not hand-typed — plus 30 new Go tests under `app/internal/mcp/`.
- MCP Prometheus metrics: `mytoolkit_mcp_requests_total{method,status}`/`mytoolkit_mcp_request_duration_seconds{method}` for every JSON-RPC method, `mytoolkit_mcp_tool_calls_total{tool,status}`/`mytoolkit_mcp_tool_call_duration_seconds{tool}` for `tools/call` specifically, and `mytoolkit_mcp_sessions_total` — recorded by one `server.AddReceivingMiddleware` hook (`app/internal/mcp/metrics.go`) covering all 16 tools and every JSON-RPC method, no per-handler instrumentation. Kept as a metric family separate from `mytoolkit_http_*`/`mytoolkit_tool_usage_total` (distinct client population). `GET /metrics` is mounted alongside the MCP JSON-RPC endpoint on the same `http.ServeMux` when `--transport http` — `stdio` has no listening port, so it isn't exposed there (inherent to the transport, not a gap).
- Grafana dashboard: a new "MCP Server" row (12 panels — tool call rate/error-rate/latency percentiles by tool, request rate by JSON-RPC method, session count, current-totals table, and a tool-call ranking) added to `observability/mytoolkit-dashboard.json`. `observability/prometheus.yml` gained a `mytoolkit-mcp` scrape job (the optional Compose `mcp` profile service); `helm/mytoolkit/templates/mcp-deployment.yaml` gained `prometheus.io/scrape` annotations and a new optional `mcp-servicemonitor.yaml`. Verified end-to-end against the real docker-compose stack: real `initialize`/`tools/call` JSON-RPC traffic against `mytoolkit-mcp`, confirmed present in Prometheus via direct API query, and confirmed rendering in the provisioned Grafana dashboard via Grafana's own datasource-proxy API (not just visual inspection of the JSON).

### Changed

- `app/go.mod` now pins `go 1.26.5` (previously `1.25.0`), and the Dockerfile's builder stage moved from `golang:1.25-alpine` to `golang:1.26.5-alpine` to match. `README.md`'s toolchain table and Technology Stack entry updated accordingly.
- Dependencies refreshed via `go get -u ./... && go mod tidy`: notably `github.com/prometheus/client_golang` v1.23.2 → v1.24.0, `github.com/prometheus/common` v0.66.1 → v0.70.0, `github.com/prometheus/procfs` v0.16.1 → v0.21.1, `github.com/spf13/pflag` v1.0.9 → v1.0.10, `github.com/go-openapi/swag` v0.19.15 → v0.27.3 (plus its now-modularized `github.com/go-openapi/swag/*` sub-packages), and `golang.org/x/{mod,net,oauth2,sync,sys,tools}` to their latest patch/minor releases. Verified with `go build ./...`, `go vet ./...`, `go test ./...`, and `go mod verify && go mod tidy -diff` against the real module graph — no source changes required.

## [1.0.0] - 2026-07-10

### Added

- Initial implementation of MyToolkit: a Go web application and CLI exposing 15 tools.
- REST API under `/api/v1/tools/<slug>` for every tool, with a shared JSON success/error envelope.
- CLI subcommand per tool, with a shared `--in`/`--out` (file-or-stdio) convention.
- `mytoolkit --version`/`-v`, reading from the repo-root `VERSION` file — the single source of truth also used to tag Docker images.
- Server-rendered web UI with a Material Design 3–inspired dark/light theme; pages accept a `?theme=light|dark` override for deterministic screenshots/demos.
- `/healthz`, `/readyz`, `/metrics` (Prometheus), and `/api/v1/metrics/ranking` (usage ranking) endpoints.
- Structured JSON logging via zerolog, with request correlation IDs.
- Multi-stage, multi-arch (linux/amd64, linux/arm64) Dockerfile, validated with `docker buildx`, and `docker-compose.yml`.
- `make docker-push`: interactive Docker Hub publish (hidden credential prompt, `--password-stdin`, never logged).
- Helm chart under `helm/mytoolkit` — Prometheus scrape annotations, `helm-docs`-generated chart README, deployed and `helm test`-verified against a real `kind-multinodes` cluster.
- Unit tests for every tool's business logic, plus per-feature documentation (`docs/api|cli|testing`, with a Mermaid workflow diagram each) and `.skills/`.
- JWT Encode/Decode: multi-algorithm support via `golang-jwt/jwt/v5` (already a dependency, previously only used for HMAC). Adds RSA (`RS256`/`RS384`/`RS512`), RSA-PSS (`PS256`/`PS384`/`PS512`), ECDSA (`ES256`/`ES384`/`ES512`), and EdDSA alongside the original HMAC algorithms — 13 total — selectable via a new web UI combobox, plus the existing CLI `--algorithm` flag and REST `options.algorithm`. `HS256` remains the default, unchanged. Asymmetric algorithms sign/verify with a new `key` parameter (PEM-encoded — private key to encode, public key to verify a decode; CLI: `--key <file|->`; REST/web: `options.key`), independent of the existing HMAC-only `secret`. Verification derives which of `secret`/`key` applies from the token's own `alg` header, not a caller hint, so pasting the wrong one fails verification cleanly (`valid: false`) instead of erroring or silently succeeding — verified directly, including a full round trip through the CLI, REST, and the actual running web page against a real `openssl`-generated RSA key pair.
- Shared navigation shell on every page: a hamburger menu opening a Material Design 3 "modal navigation drawer" listing all tools (with a scrim, closable via scrim click/✕/Escape); a client-side search bar (`#tool-search`) that filters tools live by name and description with zero network calls; a "← Back to Home" button on every tool page; and a footer (developer/contact links) on every page.
- M3 component pass across the web UI, following `m3.material.io`'s spacing, buttons, icon-buttons, checkbox, lists, navigation-bar, navigation-drawer, radio-button, search, switch, and text-fields guidance: a 4dp spacing scale and state-layer opacity tokens in `theme.css`, restyled checkboxes and a new switch component (single on/off settings like "Decode" now use a switch instead of a checkbox), consistent text-field focus rings, and shared list-item styling reused by both the nav drawer and search results.
- `internal/registry/registry_test.go`: a regression test (`TestToolJSONFieldsAreLowercase`) locking in `registry.Tool`'s JSON contract.
- `internal/web/static/icons/favicon.svg`, referenced via `<link rel="icon">`.
- JSON Tree Viewer overhaul: error messages now report the exact 1-indexed line and column of the problem (e.g. `invalid character '}' looking for beginning of value (at line 4, column 1)`), not just a bare parser message; trailing content after a complete JSON value (e.g. `{"a":1}garbage`, or two concatenated values) is now rejected instead of silently ignored; the web page gained an explicit "Generate Tree View" action (conversion no longer happens on every keystroke — large pasted API responses made that wasteful and janky), plus "Expand All"/"Collapse All"/"Clear" buttons; tree nodes are now color-coded by value type (VS Code–inspired: keys, strings, numbers, booleans, and null each get a distinct, theme-aware color) and show `Object {N keys}`/`Array [N items]` summaries instead of a generic `type(size)` placeholder.
- JSON Formatter web page overhaul: now runs entirely client-side via the browser's native `JSON.parse()`/`JSON.stringify()` (no `fetch()` call from the interactive tool), so validation results and error messages exactly match real Node.js/browser behavior instead of Go's `encoding/json` wording. New, explicit actions replace live-as-you-type formatting: "Validate JSON" (green success banner on valid input, red error banner with the exact `JSON.parse()` message on invalid input, output untouched either way), "Beautify" (2-space indent), "Minify", "Copy Output", "Clear". Adds a new `.success-banner` style (light/dark) alongside the existing `.error-banner`. REST (`POST /api/v1/tools/json-format`) and CLI (`mytoolkit json-format`) are unchanged, still full Go implementations for scripted use; as with JSON to TOON Converter, `mytoolkit_tool_usage_total{tool="json-format"}` no longer reflects web page usage, only REST/CLI.
- Character, Word & Line Counter: added a "Clear" button that empties the input and resets all four stats to `0` (previously required manually selecting and deleting the textarea contents).
- YAML Formatter overhaul, driven by a re-read of the YAML spec (yaml.org/spec/1.2.2): (1) **fixed a real spec-compliance bug** — multi-document streams (`---`-separated) previously had every document after the first silently discarded; `Format` now decodes and reformats the entire stream, and the encoder re-inserts `---` between documents automatically. (2) Added a `style` option (`block`, default, or `flow`) that forces consistent collection style across the whole document — the YAML equivalent of JSON Formatter's pretty/minify, and always lossless per the spec ("node style is a presentation detail... not reflected in the representation graph"). Previously the formatter only re-indented and left flow-style input (`{a: 1}`) untouched, so mixed-style input never actually got consistent formatting. New `--style` CLI flag and web "Style" select. A whitespace/comment-only input (which decodes to zero YAML documents without a parse error) is now treated as empty input rather than silently returning an empty result. Verified and documented actual `yaml.v3` behavior for comments, anchors/aliases, merge keys, tab-indentation rejection, and the "Norway problem" (`yes`/`no`/`NO`) — all preserved correctly or already spec-correctly rejected; see `.skills/yaml-format/SKILL.md`.
- Grafana dashboard for the `prometheus`/`grafana` `docker-compose.yml` services: `observability/mytoolkit-dashboard.json` covers every metric the app exposes — HTTP request rate/error-rate/latency percentiles by tool and status (`mytoolkit_http_requests_total`, `mytoolkit_http_request_duration_seconds`), per-tool usage (`mytoolkit_tool_usage_total`, the same data behind `GET /api/v1/metrics/ranking`), and Go runtime/process health (goroutines, memory, GC, CPU, open FDs, network I/O). Auto-provisioned via `observability/grafana/provisioning/{datasources,dashboards}/*.yml` — `docker compose up --build` now gives a working dashboard with zero manual Grafana setup. Every query was verified against a real running binary's `/metrics` output, and the whole stack was verified end-to-end (real traffic, real Grafana login, screenshotted rendering) — see `.skills/observability/SKILL.md`.
- Interactive Swagger/OpenAPI documentation at `GET /swagger/index.html` (`swaggo/swag` + `swaggo/http-swagger`), covering all 19 JSON REST endpoints: every `/api/v1/tools/<slug>` tool endpoint, `GET /api/v1/tools`, `GET /api/v1/metrics/ranking`, `/healthz`, `/readyz`. Generated from `@`-comment annotations via a new `make swagger-gen` target (pinned `go run github.com/swaggo/swag/cmd/swag@v1.16.6`, no separate install needed) into `app/docs/` (committed, like the Helm chart's generated README). Each of the 9 tools wired via the generic `handlers.Wrap(...)` got a small named wrapper function (e.g. `base64Handler()`) purely to carry its annotation, since `swag` needs a real function declaration to attach a doc comment to. New `internal/httpapi/swagger_test.go` regression test asserts every tool in `registry.All()` has a corresponding Swagger path, so a future tool added without annotations fails a test instead of silently missing from the docs. `/metrics` (Prometheus text format) is deliberately not included — it isn't JSON/OpenAPI-shaped. Verified end-to-end: a real running binary's `/swagger/doc.json` and `/swagger/index.html`, and a Playwright-driven "Try it out" execution against the live `base64` endpoint returning a real signed response. See `.skills/swagger/SKILL.md`.
- `make helm-set-appversion`: syncs `helm/mytoolkit/Chart.yaml`'s `appVersion` field to the root `VERSION` file (portable `sed -i.bak` + `rm`, works on both GNU and BSD/macOS `sed`). Now a prerequisite of `make helm-docs`, so every chart-docs regeneration keeps `appVersion` from silently drifting out of sync with `mytoolkit --version`/the Docker image tag. The chart's own `version:` field (semver of the chart itself) is untouched.

### Changed

- Go/HTML/CSS/JS source (`cmd/`, `internal/`) moved under `src/` (its own Go module root), separating application source from planning, documentation, and deployment files at the repo root.

### Fixed

- `README.md` previously listed a non-existent "SHA-1024" hash algorithm; the Hash Generator implements MD5, SHA-1, SHA-256, and SHA-512.
- The Helm chart's test hook was initially placed at `tests/test-connection.yaml`; Helm only discovers hooks under `templates/`, so it was silently never run until moved to `templates/tests/test-connection.yaml`.
- Verification pass across all 12 tools: added missing Mermaid workflow diagrams to 7 `docs/api/<tool>.md` files that didn't have one (base64, case-convert, hash-gen, jwt, qrcode, text-count, url-encode).
- `docs/api/url-encode.md` documented a nonexistent `options.mode` field; the real field is `options.decode` (boolean). Fixed to match `urlencode.Options`.
- `docs/cli/url-encode.md`'s example used `echo` (which appends a trailing newline that gets percent-encoded as a stray `%0A`); switched to `echo -n` and documented why.
- `docs/cli/json-tree.md`'s example output used a hand-typed compact JSON format that didn't match the real `json.MarshalIndent` output; corrected to the actual (fully expanded) output.
- `docs/api/json-format.md` and `docs/api/yaml-format.md` error examples used unverified, hypothetical parser error messages; both now include the exact request that reproduces the documented error message.
- `registry.Tool` had no `json:"..."` tags, so `json.Marshal` emitted capitalized Go field names (`Slug`, `Name`, …). The new search bar's JS reads lowercase (`t.slug`, `t.name`, …), so every search silently returned zero results — no thrown error, just nothing found. Caught by an end-to-end Playwright test, not a unit test or code review. Fixed with explicit lowercase `json` tags; this also fixes the same latent inconsistency in `GET /api/v1/tools`'s response shape.
- No favicon was ever defined, so every page load triggered a browser-automatic `/favicon.ico` request that 404'd (a real, if benign, console error) — fixed.
- `README.md`'s Architecture `sequenceDiagram` Mermaid block failed to render on GitHub ("Expecting '()', ... got 'NEWLINE'") because it used unescaped `<name>`/`<slug>` placeholders in unquoted participant/message text; GitHub's Mermaid parser doesn't reliably handle HTML-entity-escaped angle brackets there. Fixed by rewording the diagram to avoid special characters entirely.
- `tool-common.js`'s `collectOptions()` only coerced `<input type="number">` values to a JSON number; any `<select>`-based numeric option (e.g. YAML Formatter's `indent`, QR Code's `size`) was sent as a JSON string, which `json.Unmarshal` into a Go `int` field rejects outright — every web-page request using those selects silently 400'd with `invalid options object`.
